# COO・CSR版の測定方法

第1・第2層の重みを疎配列から直接計算する。第3層の重みと全バイアスは変更しない。Arduino上で非圧縮の行列を復元せず、中間出力ベクトルだけを確保する。

2026年10月30日以降の測定閾値は、0.01、0.005、0.02、0.03とする。70次元・0.02の測定はユーザー報告で完了しており、現在は両層の閾値0.03を測定する準備をしている。現在の配置と確認する数値は[測定条件.md](測定条件.md)を参照する。

## 作成したファイル

| 保存先 | 役割 |
|---|---|
| `scanner_coo/scanner_coo.ino` | 第1・第2層をCOOの値・行番号・列番号から計算する |
| `scanner_csr/scanner_csr.ino` | 第1・第2層をCSRの値・列番号・行開始位置から計算する |
| 各フォルダの `measurement.h` | 同一の計時・容量集計・画像出力・シリアル操作を提供する |
| 各フォルダの `evaluation_data.h` | 非圧縮版と同じ固定評価入力を持つ |

既存の `scanner_ver3` は非圧縮版として残す。現在の `scanner_coo` と `scanner_csr` には、70_70モデル・両層の閾値0.03の重みヘッダーを配置している。別の条件へ切り替える場合は、使用する閾値で生成し、次の手順で対応するフォルダにコピーしてからコンパイルする。

## 圧縮ヘッダーを用意する

1. 非圧縮でRAM不足となった同じモデルの `model_parameters.h` を、`train_python/compress_weights.py` に指定する。
2. 第1層・第2層の閾値を指定してCOO・CSRを同時生成する。閾値が共通なら `--threshold`、層ごとなら `--threshold1` と `--threshold2` を使う。
3. 生成先の `coo/model_parameters.h` を実験フォルダ内の `scanner_coo/model_parameters.h` にコピーする。
4. 同じ生成先の `csr/model_parameters.h` を `scanner_csr/model_parameters.h` にコピーする。

両形式で同じモデル・同じ層ごとの閾値・同じ枝刈り後の重みを使う。閾値を変更した場合は新しい条件として保存する。単に元の非圧縮ヘッダーを置いたり、COOとCSRを入れ替えたりしても使えない。

次元数は重みヘッダーの `MODEL_HIDDEN_SIZE1` と `MODEL_HIDDEN_SIZE2` から自動で決まるため、スケッチの数字を手動で変更する必要はない。両方の隠れ層を増やしたモデルにも、第1隠れ層を固定したモデルにも対応する。

## Arduinoで測定する

1. `scanner_coo/scanner_coo.ino` をArduino IDEで開く。
2. 同じボード・ビルド設定でコンパイルし、フラッシュ・静的RAM使用量を記録する。
3. 実機へ書き込み、シリアルモニターを9600 baudで開く。
4. `i` を送り、次元数、`storage=coo`、2つの閾値、`model_source_sha256`、`evaluation_source_sha256` を確認する。
5. `r` を送る。100回の予備推論後、1,000回の推論を5セット測定する。
6. `parameter_bytes`、`compression_ratio_percent`、5セット分の時間、`mean_inference_us` を記録する。
7. `PPM_BEGIN` と `PPM_END` の間のP3から最後の画素行までを、条件が分かる別名のPPMへ保存する。`MEASUREMENT_COMPLETE` を確認する。
8. `MSE測定/mse_calculator.html` で、基準 `reference_3x3.ppm` と出力PPMを比較する。
9. 同じ手順を `scanner_csr/scanner_csr.ino` で行い、`storage=csr` を確認する。

## 容量と計時の範囲

- `parameter_bytes` は、第1・第2層の値・索引、第3層の重み、全バイアスのsizeof合計。NNZ=0の配列のダミー1要素も容量に含む。
- `dense_parameter_bytes` は同じ構成の全パラメータを非圧縮float配列で保存した場合の容量。
- 圧縮率＝圧縮後容量÷非圧縮容量×100。0に近いほど小容量で、100%を超える場合もある。
- 元の重みを枝刈りしたことでMSEが変わる可能性がある。COOとCSRは同じ枝刈り後のモデルを表す。
- 計測区間には推論、共通の入力参照・ループ・volatile集計を含む。索引の事前確認、画像生成、整数化、シリアル通信、センサー読み取り、LED待機は含めない。
- 入力は非圧縮版と同じ `dimention_40/40_dimention_before.ppm` 由来の固定9画素。両形式の `evaluation_data.h` は同一内容である。評価入力を変更するときは全比較条件で同じ入力にそろえる。
- コンパイル成功だけで搭載可とはせず、推論・画像出力の完了も確認する。

スケッチの起動・接続だけでは推論を始めず、`r` を受信してから測定する。センサーとLEDは操作しない。
