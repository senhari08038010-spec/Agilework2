# COO・CSR測定条件

現在の測定対象は3 → 100 → 100 → 3、両層の閾値0.005。2026年10月30日、既存ノートブックのデータ・学習条件で100_100の元モデルを新規に学習し、COO・CSRを生成した。実機への書き込み・測定はこれから行う。

## 元モデルと学習条件

- 元の非圧縮重み：`train_python/学習/100_100/model_parameters.h`
- 元の重みのSHA-256：`1652d72a554967bfbdbdc0cf42f8e504ac472ab81aed64448048eb453df0b5dd`
- 学習実行スクリプト：`train_python/学習/100_100/train_100_100.py`
- 元のノートブック：`train_python/train_L1_normalization.ipynb`。ノートブック自体は変更していない
- 入力：`scanner_ver2/before_1669_59.ppm`の9画素と、`train_python/week3_6_6.ppm`の上4行・24画素を結合した33画素。各RGBを255で割ってfloat32へ正規化
- 正解：従来と同じ2枚の画像を最近傍で3×3、6×4に変換した33画素
- 学習：CPU、Adam、学習率0.01、50,000回、MSE＋全層の重みに対するL1正則化（係数0.000001、バイアスは除く）
- 今回は再現用に乱数シード42を指定した。元のノートブックにはシード指定がない
- 元モデル、チェックポイント、学習ログ・条件・実際に使用した入出力は`train_python/学習/100_100/`に保存

学習データ・正解データが既存ノートブックの計算結果と一致し、書き出した6配列がチェックポイントのfloat32値と一致することを確認した。学習時のMSEと、今後の固定9画素による実機MSEは分けて記録する。以後の閾値比較では再学習せず、この同じ元モデルを使う。

## 圧縮・評価の共通条件

- 圧縮対象：`weight_1`と`weight_2`。重みの絶対値が閾値未満の場合だけ0にする
- 第3層の重みと全バイアスは元モデルのまま保持する
- COOとCSRは同じ枝刈り後の行列から生成する
- 評価入力：従来と同じ`dimention_40/40_dimention_before.ppm`由来の固定9画素。両形式の`evaluation_data.h`は変更していない
- 基準画像：`MSE測定/reference_3x3.ppm`
- 今後の閾値候補は従来の決定どおり0.005、0.01、0.02、0.03。今回は0.005から測定する

## 閾値0.005の測定準備

生成先は`train_python/学習/100_100/compressed_t1_0p005_t2_0p005/`。各形式の`model_parameters.h`を`scanner_coo/`と`scanner_csr/`へ配置した。推論処理・測定処理を変更せず、ヘッダーから次元数を自動取得する。

`i`を送って次の値を確認する。

| 項目 | COO | CSR |
|---|---|---|
| `hidden_size1` | 100 | 100 |
| `hidden_size2` | 100 | 100 |
| `storage` | coo | csr |
| `compressed_layers` | 1,2 | 1,2 |
| `pruning_threshold_1` | 0.005 | 0.005 |
| `pruning_threshold_2` | 0.005 | 0.005 |
| `weight_1_nnz` | 37 | 37 |
| `weight_2_nnz` | 115 | 115 |
| `parameter_bytes` | 2924 | 2974 |
| `dense_parameter_bytes` | 43212 | 43212 |
| 圧縮率（圧縮後÷圧縮前×100） | 6.766639% | 6.882347% |

パラメータ容量は配列・索引のsizeof合計であり、Arduino全体のフラッシュ・RAM使用量とは別の値である。

1. Arduino IDEで`scanner_coo/scanner_coo.ino`を開き、Arduino UNO R4 WiFiへ書き込む。
2. シリアルモニターを9600 baudで開き、`i`を送って上記の条件と`model_source_sha256`・`evaluation_source_sha256`を確認する。
3. `r`で測定を開始し、`MEASUREMENT_COMPLETE`まで確認する。容量、圧縮率、推論時間とビルド時のフラッシュ・静的RAM使用量を記録する。
4. `PPM_BEGIN`と`PPM_END`の間のP3形式の内容を、生成先の`coo/coo_100_t0p005.ppm`へ保存する。シリアル出力全体も同じフォルダへ保存する。
5. `MSE測定/mse_calculator.html`で基準画像と比較し、MSEを記録する。
6. CSR版も`scanner_csr/scanner_csr.ino`を書き込んで同じ手順で測定し、PPMを生成先の`csr/csr_100_t0p005.ppm`へ保存する。

0.005の実機測定は未実施。準備時のPC上の推論一致確認・Arduino向けコンパイルの結果は、生成先の`validation_report.json`と各形式の`arduino_build.txt`に保存する。
