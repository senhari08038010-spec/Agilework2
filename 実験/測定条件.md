## 共通条件

- モデル構成：3 → 70 → 70 → 3。両隠れ層とも70次元
- 元の非圧縮重み：`train_python/学習/70_70/model_parameters.h`
- 元の重みのSHA-256：`96bf967cfafd9037c5a7ea57f6ec4fe34c01da292988d391ba96f8d6d3cc07a4`
- 圧縮する配列：`weight_1`と`weight_2`
- 変更しない配列：第3層の重みと全バイアス
- 枝刈り：重みの絶対値が閾値未満の場合だけ0にする
- 評価入力：`dimention_40/40_dimention_before.ppm`由来の固定9画素。COO・CSRの`evaluation_data.h`は同じ内容を維持する
- 基準画像：`MSE測定/reference_3x3.ppm`
- 学習はやり直さず、同じ元の重みから各閾値の圧縮版を生成する

## 次に測定する閾値0.005

圧縮データは`train_python/学習/70_70/compressed_t1_0p005_t2_0p005/`に保存し、各形式の`model_parameters.h`を`scanner_coo/`と`scanner_csr/`へ配置した。元の重み、評価入力、測定処理は共通のままとする。

`i`を送ったとき、次の値で条件を確認する。

| 項目 | COO | CSR |
|---|---|---|
| `hidden_size1` | 70 | 70 |
| `hidden_size2` | 70 | 70 |
| `storage` | coo | csr |
| `compressed_layers` | 1,2 | 1,2 |
| `pruning_threshold_1` | 0.005 | 0.005 |
| `pruning_threshold_2` | 0.005 | 0.005 |
| `weight_1_nnz` | 39 | 39 |
| `weight_2_nnz` | 90 | 90 |
| `parameter_bytes` | 2186 | 2199 |
| `dense_parameter_bytes` | 21852 | 21852 |

容量は生成ヘッダーの配列・索引の合計値であり、Arduino全体のフラッシュ・RAM使用量ではない。

1. Arduino IDEで`scanner_coo/scanner_coo.ino`を開き、Arduino UNO R4 WiFiへ書き込む。
2. シリアルモニターを9600 baudで開き、`i`を送って上記の設定と元モデル・評価入力の識別情報を確認する。
3. `r`を送って測定する。`MEASUREMENT_COMPLETE`を確認し、容量、圧縮率、推論時間とビルド時のフラッシュ・静的RAM使用量を記録する。
4. `PPM_BEGIN`と`PPM_END`の間のPPMを、`train_python/学習/70_70/compressed_t1_0p005_t2_0p005/coo/coo_70_t0p005.ppm`として保存する。必要に応じてシリアル出力全体も同じフォルダへ保存する。
5. `MSE測定/mse_calculator.html`で基準画像と比較し、MSEを記録する。
6. CSR版も`scanner_csr/scanner_csr.ino`を書き込んで同じ順に測定する。PPMは上記生成フォルダの`csr/csr_70_t0p005.ppm`へ保存する。

PCでの検証・Arduino向けコンパイルと、実機への書き込み・測定は分けて記録する。0.005の実機測定結果は、測定後に記入する。

## 0.02・0.03へ進むとき

同じ元の非圧縮ヘッダーを指定し、`compress_weights.py`の`--threshold`を0.02または0.03にする。生成したCOO・CSRのヘッダーをそれぞれの測定用スケッチへ配置し、`i`で両層の閾値を確認してから測定する。PPMと測定記録は閾値別の生成フォルダに分けて保存する。
