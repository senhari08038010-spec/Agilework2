# 測定方法（非圧縮版）

対象は `scanner_ver3/scanner_ver3.ino`。測定モードでは保存済み入力を使い、センサー・LED・ボタンを使用しません。起動やシリアル接続だけでは測定を開始しません。

## 入力と基準画像

- 入力：`train_python/test_week3.ppm` の3×3・9画素を、左上から行順・RGB順に並べ、各値を255で割った固定値。`scanner_ver3/evaluation_data.h` に保存しています。
- 基準：`MSE測定/reference_3x3.ppm`。ノートブックの正解画像 `train_python/img/reference_image1_cmyk_large.png` を、ノートブックの `INTER_NEAREST` と同じ位置（左上、幅の1/3、幅の2/3）から3×3にサンプリングしたP3画像です。
- 入力・基準とも、次元数を変えても同じものを使用します。この9画素は現行ノートブックの学習にも含まれるため、MSEは学習に含まれるデータに対する評価です。未知データへの精度を示すものではありません。
- 元の入力を変更してもヘッダーは自動更新されません。固定入力を変更する場合はヘッダーと対応する基準画像も更新し、以降の全条件でそろえてください。入力ファイルのSHA-256をヘッダーとシリアル出力に残しています。

## 実機で測定するとき

1. 学習後に出力した `model_parameters.h` を同じスケッチフォルダに置き、`HIDDEN_SIZE2` と配列長を合わせます。現在は40次元です。今回の追加では学習やパラメータ変更は行っていません。
2. Arduino IDEで使用ボードとビルド設定をそろえ、コンパイルします。表示されるフラッシュ使用量・静的RAM使用量とログを保存します。これは測定プログラムが自動取得する値ではありません。
3. 実機へ書き込み、9600 baudのシリアルモニターを開きます。`i` を送ると次元数・容量・入力情報だけを表示します。
4. 測定を行うときに `r` を送ります。100回の予備推論後、1,000回の推論を5セット計時します。各セットは固定入力の先頭から同じ順序で繰り返します。
5. `parameter_bytes` を保存容量［B］、`mean_inference_us` を平均推論時間［µs／回］として記録します。5セット分の経過時間・1回当たり時間・出力集計値もログに残します。非圧縮版の圧縮率は100%です。
6. `PPM_BEGIN` と `PPM_END` の間の、`P3` から最後の画素行までだけをコピーし、`MSE測定` 内に条件が分かる名前（例：`dense_40_output.ppm`）で保存します。マーカーや他のログは含めません。
7. `MSE測定/mse_calculator.html` で、基準画像に `reference_3x3.ppm`、比較画像に保存した出力PPMを読み込み、MSEを記録します。
8. 正しいサイズ・全画素の画像出力と `MEASUREMENT_COMPLETE` を確認して、実機動作を「可」と記録します。途中停止や `MEASUREMENT_ERROR` があれば正常完了として扱わず、ログを残します。

## 測定範囲

- 計時には `micros()` を使用し、計時後のunsigned差分を1,000で割ります。5セットの1回当たり時間の平均を表示します。
- 計時には共通の入力参照・ループ・`volatile` 変数への出力集計が含まれます。センサー読み取り、LED待機、PPM生成、整数化、シリアル出力は含めません。出力集計は計算省略を防ぐため、COO・CSRでも同じ方法を使用してください。
- RGB出力は255倍後、0〜255に制限して小数部分を切り捨てます。NaN・無限大の出力がある場合は正常完了しません。
- `parameter_bytes` は6つの重み・バイアス配列の `sizeof` 合計です。画像バッファや入力配列は含めず、それぞれ別項目で表示します。`predict_intermediate_arrays_bytes` は2つの中間配列だけの計算値で、総スタック量や総RAM量ではありません。
- この測定処理は現在の非圧縮ヘッダー用です。COO・CSRに進む際は、疎形式の `predict()` と、索引を含めた容量集計に対応させる必要があります。

通常のセンサー読み取りを使う場合は、スケッチ冒頭の `MEASUREMENT_MODE` を `0` にします。元のセンサー処理はそのまま残しています。
